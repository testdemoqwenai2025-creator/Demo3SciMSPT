# Security Policy

## 📢 Reporting a Vulnerability

Thank you for helping keep the Demo3SciMSPT project and our users safe!

## Reporting Vulnerabilities

### How to Report

Create a private **[Security Advisory](../../security/advisories/new)** on GitHub.

Please include:
- Description of the vulnerability
- Steps to reproduce
- Potential impact
- Suggested fix (if any)

### What to Expect
- **Response**: Within 48 hours
- **Resolution**: As appropriate for severity
- **Credit**: Public acknowledgment (unless you prefer otherwise)

## Scope

This security policy applies to:
- The Demo3SciMSPT public demo repository
- Associated demo deployments
- Example code and documentation provided

### Out of Scope
- Third-party dependencies (reported upstream)
- Local development environments
- Unmodified template/example code

## Security Principles

### For This Demo Repository
1. **No sensitive data**: Demos never contain real user data
2. **Environment-specific configs**: Secrets managed via environment variables
3. **Secure defaults**: Examples follow security best practices
4. **Regular updates**: Dependencies kept current

### Phase 3A Demo Security Notes

The public demo showcases AI-native architecture concepts:

- **MAOL Demo**: Simulated orchestration (no real AI backend)
- **Neural Tracking UI**: Visualization only (tracking disabled)
- **Plugin System**: Sandboxed examples (safe mode)
- **Intelligence Graph**: Sample data only (no real knowledge base)

## Best Practices for Users

When using this demo code:

1. **Review before deploying**: Understand what each component does
2. **Change default credentials**: Never use example passwords
3. **Enable security features**: Turn on all available protections
4. **Keep updated**: Pull latest security patches
